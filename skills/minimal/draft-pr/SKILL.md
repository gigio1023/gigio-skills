# Draft PR

Commit and push the requested work, and publish it as a draft PR when the user asks for one. Do exactly the Git and forge writes the request covers: commit-only stops after commits, push-only pushes without opening a PR, and a PR request includes the commits and push it needs without asking again. A request to write PR copy does not authorize branch, push, or forge writes. None of these covers issue comments, issue or PR body and title edits on other items, releases, or tags unless the same request names them.

## Commits

- Stage explicit paths and leave unrelated tracked, untracked, staged, and unstaged changes alone. Use `git add -A` only when the whole worktree belongs to the request.
- Never stash automatically to clear a dirty worktree. Finish the intended commits first, then fetch and rebase if the upstream moved.
- Never add agent branding: no `Co-Authored-By` or author trailers, no `codex/` or `claude/` branch prefixes, no "Generated by" lines in commits, titles, or bodies, unless the user or the harness instruction asks for them.
- Follow the repository's message convention; without one, `<type>(<scope>): <imperative subject>` with a body only when the reason would otherwise be lost.
- One commit per independently revertible change. A failed pre-commit hook means no commit; fix in-scope failures and retry without bypassing hooks.
- Use `--force-with-lease`, never plain `--force`, and only on a clearly user-owned topic branch. Ask before rewriting a shared or ambiguous branch. Do not run `git pull --rebase` blindly in a mixed worktree.
- Verify the push with `git status -sb` against the remote; local commit output is not proof.
- If the repository uses `jj` or another VCS layer, stop before Git writes and ask for its publish path.

## Publishing a PR

- Pick the forge from the publication remote's host, not from the name `origin` or whichever CLI is installed. In a fork workflow, resolve the head and target repositories separately.
- Use authenticated `gh` for GitHub and GitHub Enterprise and authenticated `fj` for Forgejo, bound to the exact host and target repository. Do not install or authenticate a CLI on the user's behalf. Confirm the adapter works before pushing; a pushed branch is not a PR.
- On the default branch, create a descriptive topic branch first.
- New PRs are draft by default. Never silently create a ready PR.
- Assign the authenticated user (`gh api user --jq .login`, or `fj -H <host> whoami`) while keeping existing assignees. Assign someone else only when the user says so.
- Preserve meaningful existing body content such as screenshots, issue links, and reviewer context, and keep an existing title unless asked to rewrite it or it is a generated placeholder.
- Write the body to a temporary Markdown file and pass it with `--body-file`; multiline shell arguments break formatting. Before publishing, check the title and body against the final diff.
- Verify the remote PR fields after every write and report the URL, draft state, base and head, and assignees.

PR language: the user's instruction, then a language the repository states for PRs, then the language of recent PRs. Ask once when these conflict or are missing; with no answer available, use English and say which rule decided. A repository PR template wins over any default body shape.

### GitHub

```bash
gh pr list --repo <host>/<owner>/<repo> --head "<branch>" --state open \
  --json number,url,title,body,baseRefName,headRefName,headRepositoryOwner,isDraft,assignees
gh pr create --repo <host>/<owner>/<repo> --draft --base "<base>" \
  --head "<head-owner>:<branch>" --title "<title>" --body-file "$body_file"
gh pr edit "$pr_ref" --repo <host>/<owner>/<repo> --body-file "$body_file"
gh pr edit "$pr_ref" --repo <host>/<owner>/<repo> --add-assignee "$login"
```

- `gh pr list --head` takes a bare branch name, not `owner:branch`; inspect `headRepositoryOwner` before treating a result as the current branch.
- `gh pr create --dry-run` may still push Git changes. Do not use it as a no-write probe.
- `--head <user>:<branch>` does not accept an organization as head owner.
- Keep the URL that `gh pr create` prints as the PR reference.

### Forgejo

`fj` 0.6.0 has no draft flag, accepts `--body-file` only on create, and merges without a confirmation prompt. See [references/forgejo-and-merge.md](references/forgejo-and-merge.md) for the Forgejo commands, token setup, and the squash-merge gates on both forges.

## Merging

Merge only on an explicit merge request for the resolved PR; create, update, or ready requests do not authorize it. Squash after the PR is open, non-draft, mergeable, and its required checks and reviews pass. Never switch merge methods, use `--admin`, remove a work-in-progress prefix, or delete the head branch merely to make a merge succeed; do those only when the user asks. Claim a merge only when the forge shows it merged.
